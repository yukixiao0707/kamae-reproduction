# 相比于 A 的复现新增的工作

在 A 已完成的五阶段预处理管道及 128 行一致性校验基础上，新增以下工作。

## 1. 全量一致性验证

编写独立的分批验证代码，将比较范围从 128 行扩展至全部 1,000,209 行，共检查 29,006,061 个输出元素。同时记录各字段的 dtype、形状、不一致元素数、最大绝对误差和平均绝对误差。

结果：四个输出字段均完全一致，最大和平均绝对误差均为 0。

## 2. 分桶操作的精度与边界测试

新增 Bucketize 实验，分别测试 float32 和 float64 下的普通值、分桶边界、边界相邻浮点值、正负无穷和 NaN，共 32 个案例。

结果：28 个案例一致，4 个边界案例存在一个桶的差异。进一步检查模型保存重载，并直接调用 TensorFlow 分桶算子复核，确认反例可在底层算子路径重现。

## 3. 训练集拟合与独立测试集验证

按时间顺序及稳定排序键，将数据划分为 800,167 行训练集和 200,042 行测试集。词表、均值和标准差仅从训练集学习，冻结参数后再对测试集进行 Spark/Keras 比较。

新增了对未参与拟合的数据的验证，并检查测试转换前后参数保持不变。

## 4. 未知类别测试与单字段对照

在真实测试集之外，新增约 1%、5%、10% 的未知电影、职业和类型联合注入实验；另取 4096 行，分别进行只替换电影、只替换职业、只替换类型的对照实验。

连同真实测试集，共完成 7 组实验，检查自然未见输入与人工未知类别的编码行为。各组类别输出均一致，未知类别编码核对通过。

## 5. 多算子组合与逐阶段比较

在原五阶段管道上，增加 float32、float64 两条“标准化 → 乘以 0.1 → 分桶”分支，形成 11 阶段管道。除最终结果外，还比较标准化和缩放的中间输出，检查浮点误差是否影响桶编号。

结果：7 组实验中的类别、字符串和最终桶编号均精确一致；连续中间输出存在小幅浮点差异，但均在设定容差内，未观察到这些差异改变最终桶编号。

## 6. 提出并实现精度感知导出方法

在整个复现与扩展实验过程中，发现跨框架数值一致性在特定条件下会偏离。基于已观察到的离散决策差异，新增阈值精度分析、风险输入守卫和有序整数兼容比较，形成可导出的处理模块，以浮点分桶作为实现对象。

与原始导出、统一 float64、全量严格兼容进行对照：16 个配置、82,296 个测试输入实例中，原始导出有 991 个桶编号差异，统一 float64 有 53 个，严格兼容和精度感知均为 0。原四个反例全部通过；原七组组合管道未出现验收回归。

此外测量了 96 条负载与方法组合的 CPU 开销。兼容处理存在额外代价，自适应路径未在所有负载下胜出，因此结果表述为正确性改进与开销权衡。两个 SavedModel 在新进程中无需导入 Kamae 或本模块即可通过原 32 例验证。

这项工作新增了实际的转换策略与执行实现；完整问题链、实验设置、方法和结果已写入实验记录及章节初稿。
