# C 独立验证与扩展实验验收标准

制定日期：2026-11-23；在 C 的正式实验运行前确定。所有结果必须来自真实运行，不将缺失的 A 产物当作已验证。

## 1 实验范围

基线使用 A 的 `reproduction/scripts/run_movielens_pipeline.py`，覆盖用户哈希、电影字符串索引、职业独热编码、类型字符串拆分与数组索引五个阶段。CPU 本地执行。主检验使用 MovieLens 1M 全量记录，分批执行 Keras 推理，不将全量数据一次 collect 到驱动端。

## 2 分开验收的三个问题

1. A 的复现路径是否能由 C 重复：记录代码提交、数据 SHA256、环境、参数；执行 A 的原始入口，在本机生成 Parquet 与 Keras 产物，并运行原校验脚本。流程完整完成且通过原校验，即记录为“按 A 的说明独立复跑成功”。A 的旧产物不是这一步的前置条件；若以后取得，可另做文件级结果对照，但不据此阻塞当前复跑。
2. 同一拟合管道的 Spark 与 Keras 输出是否一致：用同一原始输入、同一词表和参数，核对字段、dtype、形状和数值。重新拟合时同频词表可能改变，不能将词表变化混同为翻译错误。
3. C 的扩展实验：至少新增一个 A 未使用的内置预处理操作；首选 BucketizeTransformer。自行构建、导出、重新加载模型；包括常规有限数值、分桶边界、边界相邻浮点值及 float32/float64 对比。NaN、无穷值和缺失值单列记录，不默认其跨端语义一致。

## 3 判定规则

- 整数、类别索引、布尔值及独热编码 0/1 必须逐元素完全一致，不允许以浮点容差掩盖索引差异。
- 一般浮点值使用 `abs(a-b) <= 1e-6 + 1e-6*abs(a)`，记录原始 dtype、最大绝对误差、平均绝对误差、不通过元素数及非有限值位置。使用 float64 统计误差，不先把两端强制降为 float32。
- 同时保存原始张量形状与逻辑特征形状。仅允许明确记录的长度为 1 的包装维度转换，禁止无条件 reshape 掩盖维度不匹配。
- 缺失值和 NaN 独立比较掩码；一端报错或掩码不同必须记录为不支持/不一致。不得直接删掉失败案例。
- 比较模型保存前和重新加载后输出；整数要求精确，浮点使用同一容差。
- 基线全量成功才标记基线通过；扩展的边界失败不改阈值、不自动修库，而是保留反例并限定结论。

## 4 交付

保存环境与产物清单、数据哈希、命令与退出码、逐列统计 CSV、失败样例、扩展模型和图表，提供 B 可引用的实验章节。每项明确区分已运行通过、已运行失败、未运行和缺少外部产物。
